## TL;DR

1. **Код маленький, чистый и читаемый**, без зависимостей, на Swift 6 со строгой конкурентностью. Хорошая база.
2. **Есть реальные риски потери данных**: поиск рабочей папки может найти чужую `photos/`, а Esc, Empty Trash и Return срабатывают без подтверждения и без undo.
3. **С точки зрения culling это пока «сетка с выбором», а не инструмент отбора.** Нет главного цикла: крупный просмотр → решение одной клавишей → следующий кадр. Нет клавиатурной навигации, зума 100%, сравнения похожих кадров, а результат работы не сохраняется.
4. **Camera Roll опасен по своей модели**: «всё неотмеченное — удалить» применяется ко всей Фототеке сразу, хотя пользователь видел только её малую часть.
5. **Производительность упрётся в первые же тысячи фото**: тамбнейлы не отменяются, кэш без лимита по памяти, файловые операции на main thread, Camera Roll грузит метаданные каждого ассета.
6. **Тестов нет**, хотя `AGENTS.md` требует TDD. Стор не тестируется: библиотеки зашиты статически.

## Что хорошо

- **Простота.** Плоская структура, понятные имена, один `@Observable` стор, нет базы. Файловая система — источник правды.
- **Ноль внешних зависимостей.** ImageIO, PhotoKit, SwiftUI — только нативное.
- **Swift 6 + `SWIFT_STRICT_CONCURRENCY: complete`**, `@MainActor` стор.
- **Правильная загрузка тамбнейлов в ImageIO**: `CGImageSourceCreateThumbnailAtIndex` с учётом ориентации, `kCGImageSourceShouldCache: false`.
- **Продуманный drag-select.** Операция фиксируется на старте, обратный ход возвращает выпавшие кадры к снимку. Так работает «покраска» в Lightroom и Finder.
- **Фильтры Keep/Delete перед коммитом.** Можно посмотреть, что останется и что уйдёт, прежде чем жать кнопку.
- **Есть страховки**: `canMutate` не трогает файлы внутри `.app`. Кнопка коммита пропадает, если ничего не отмечено, поэтому одним жестом всю папку не удалить. Есть внутренняя корзина с Restore. Camera Roll удаляет в системные «Недавно удалённые», и система показывает свой диалог подтверждения.
- **Задержка 120 мс** перед превью, чтобы проезд мышью не вспыхивал оверлеем.
- **Хорошая документация** в `project.md`: поведение, данные, архитектура.

## Проблемы и решения

Формат: **проблема** → где → чем грозит → **решение**. Приоритеты: P0 — данные, P1 — culling UX, P2 — производительность, P3 — качество кода, P4 — полировка.

### P0 — потеря данных и безопасность

#### 0.1. ✅ Поиск рабочей папки может найти чужую `photos/`
[PhotoLibrary.swift:22-55](Keepset/PhotoLibrary.swift:22). Без `KEEPSET_PHOTOS_DIR` приложение поднимается до 12 уровней вверх от cwd и от бандла и берёт первую папку с именем `photos`. На регистронезависимой APFS подойдёт и `~/Photos`, и любая `Photos` у родителя.
- Последствия: Keep переносит файлы пользователя в `.Trash`, а **Reset Demo Photos (`⌘⇧R`) удаляет их навсегда** ([PhotoLibrary.swift:142-156](Keepset/PhotoLibrary.swift:142): `removeItem` по каждому файлу плюс `emptyTrash`).
- **Решение:** убрать обход родителей. Порядок: env-переменная → `Application Support/Keepset/photos` (seed). Reset разрешать только для папки, которую создало приложение. Например, класть в неё маркер-файл `.keepset-sandbox` и проверять его перед удалением.
- **Сделано:** обхода родителей больше нет: `KEEPSET_PHOTOS_DIR` → `Application Support/Keepset/photos`. Папки, которые приложение создаёт само, получают маркер `.keepset-sandbox`; существующую папку из env оно не помечает. `resetFromSeed` без маркера бросает `notSandbox` и ничего не трогает. Репозиторная `photos/` помечена в git. `resolve` принимает env, seed и путь Application Support параметрами, 7 тестов в `WorkingDirectoryTests`.

#### 0.2. Esc стирает всю работу
[ContentView.swift:97-103](Keepset/ContentView.swift:97), [PhotoStore.swift:104](Keepset/PhotoStore.swift:104). Esc сначала закрывает превью, а если превью уже закрыто, снимает **все** сердца. Esc — рефлекторная клавиша. Достаточно нажать её дважды или нажать на 120 мс позже, чем закрылось превью, и сотня отметок пропадёт без возможности вернуть.
- **Решение:** Esc только закрывает превью или прерывает текущий жест. Снятие выбора — явной командой (`⌘D` / «Deselect All» в меню) с поддержкой undo (см. 0.4).

#### 0.3. Empty Trash удаляет навсегда в один клик
[TopBar.swift:80-86](Keepset/TopBar.swift:80), [PhotoLibrary.swift:132](Keepset/PhotoLibrary.swift:132). Нет подтверждения, `removeItem` минует системную Корзину.
- **Решение:** `confirmationDialog` («Delete N photos permanently? This can't be undone.»). Лучше вообще не удалять навсегда, а отправлять в системную Корзину через `FileManager.trashItem` (см. 4.1).

#### 0.4. Нет undo
Отметки, drag-покраска, Keep, Restore — ни у чего нет `⌘Z`. В culling ошибочный клик — норма.
- **Решение:** простой стек снимков `selectedIDs` в сторе (до N шагов) плюс команда Undo/Redo в меню Edit. Для Keep в Sandbox undo = restore только что перенесённых файлов. Список перенесённых известен после операции.

#### 0.5. Return коммитит удаление без подтверждения
[ContentView.swift:105-114](Keepset/ContentView.swift:105). Return — частая клавиша. Он сразу переносит все неотмеченные в корзину. Для Sandbox это обратимо через Trash, но пользователь может не знать, что Trash существует.
- **Решение:** при первом коммите показать лист подтверждения «Keep 12 · Move 230 to Trash» с напоминанием, где искать удалённое, и галкой «Don't ask again». Плюс сразу после коммита — тост «230 moved to Trash · Undo».

#### 0.6. ✅ Частичный сбой Keep рассинхронизирует состояние
[PhotoStore.swift:199-225](Keepset/PhotoStore.swift:199). Если `moveToTrash` упал на пятом файле из десяти, `photos` остаётся старым, а часть файлов уже в `.Trash`. Кроме того, `photos.removeAll` удаляет из списка и файлы, которые `canMutate` пропустил: они остались на диске.
- **Решение:** после операции, и при успехе, и при ошибке, перечитывать списки с диска (`photos = try library.loadPhotos()`), как это уже делает `restoreSelected`.
- **Сделано:** Keep, Restore, Empty Trash и Reset после операции (и при ошибке) перечитывают папку и корзину с диска (`reloadFolder`).

#### 0.7. Camera Roll: «удалить всё неотмеченное» на всю Фототеку
[PhotoStore.swift:201](Keepset/PhotoStore.swift:201). В Фототеке 20–50 тысяч снимков. Пользователь отметил 5 последних и нажал Return. В «Недавно удалённые» уходит вся библиотека, кроме пяти. Системный диалог PhotoKit спасает, только если человек прочитает число.
- **Решение (сразу):** в Camera Roll коммит применяется только к **рабочему срезу** (день / событие / диапазон дат, см. 1.8), а не ко всей библиотеке. До появления срезов — жёсткий потолок (например, не больше 500 удалений за раз) и своё подтверждение с числом крупным шрифтом.

#### 0.8. Restore теряет исходное имя файла
[PhotoLibrary.swift:117,127](Keepset/PhotoLibrary.swift:117). При конфликте в `.Trash` файл становится `cat-2.jpg`, и Restore возвращает его под этим именем.
- **Решение:** при переносе в корзину запоминать исходное имя (sidecar-JSON в `.Trash` или расширенный атрибут), при Restore возвращать исходное имя, если оно свободно. Если перейти на системную Корзину (4.1), проблема исчезнет сама: у Finder есть «Put Back».

### P1 — Culling UX (критический взгляд)

#### Диагноз

Culling — это быстрый проход по съёмке с решением по каждому кадру. Цикл в инструментах вроде Photo Mechanic, Lightroom, FastRawViewer, Narrative Select:

| Шаг | Что нужно | Как сейчас в Keepset |
|---|---|---|
| 1. Открыть съёмку | Выбрать папку / карточку / день | Одна захардкоженная папка или вся Фототека |
| 2. Смотреть крупно | Один кадр на весь экран, ←/→ | Только hover-превью, пока мышь на лупе |
| 3. Решить | Одна клавиша (P / X / 1–5) + автопереход | Только клик мышью по плитке |
| 4. Проверить резкость | Зум 100% в точку | Нет; превью 2200 px, на 5K-экране меньше 1:1 |
| 5. Сравнить похожие | 2–4 кадра рядом, группы серий | Нет |
| 6. Пересмотреть решения | Фильтры по статусу | **Есть** (All / Keep / Delete) ✓ |
| 7. Применить | Подтверждение, обратимость | Есть, но без подтверждения и undo (см. P0) |

Шаги 2–5 — ядро culling, и их нет. При этом сам принцип **«отмечаю, что оставить»** хороший: он подталкивает к строгому отбору. Ниже — что сделать, чтобы он работал на больших съёмках.

#### 1.1. Нет режима просмотра (loupe) с клавиатурой — главный пробел
Превью живёт, только пока курсор на лупе размером 28 pt ([PhotoCell.swift:94-129](Keepset/PhotoCell.swift:94)). В нём нельзя поставить сердце, перейти к следующему кадру или приблизить.
- **Решение:** полноценный режим просмотра одного кадра.
  - Открыть: `Space` (как Quick Look в macOS), двойной клик или Return на сфокусированной плитке.
  - `←/→` — предыдущий / следующий кадр, `Space` / `Esc` — назад в сетку на том же месте.
  - Решение одной клавишей: `P` или `↑` — keep, `X` или `↓` — снять. Опция «автопереход после решения».
  - Индикатор «12 / 240» и сердце на кадре.
  - Hover-лупу можно оставить как быстрый peek, но основной путь — клавиатура.

#### 1.2. Нет клавиатурной навигации в сетке
Нет фокуса и курсора по плиткам. Всё делается мышью: на сотнях кадров это медленно и утомляет руку.
- **Решение:** «текущая» плитка с видимым фокусом. Стрелки двигают её, `Space` открывает loupe, `P`/`X` отмечают, `Shift+стрелки` — диапазон (как в Finder). Сетка автоскроллит к текущей плитке (`ScrollViewReader.scrollTo`).

#### 1.3. Нет зума 1:1
Резкость — причина №1 браковать кадр. На превью 2200 px её не оценить.
- **Решение:** в loupe клик или `Z` переключают между fit и 100% в точке клика, перетаскивание панорамирует. Для 100% декодировать полный размер (ImageIO, без `MaxPixelSize`) по требованию.

#### 1.4. ✅ Квадратная обрезка скрывает композицию
[PhotoCell.swift:31](Keepset/PhotoCell.swift:31) — `scaledToFill` в квадрат. Вертикальный кадр с обрезанной головой или завален горизонт в сетке не видны.
- **Решение:** переключатель «Square / Fit» (как «Aspect Ratio Grid» в Фото). В режиме Fit картинка вписывается в квадратную ячейку с полями.
- **Сделано:** переключатель из двух иконок (`square` / `rectangle.portrait`) сразу после слайдера. В режиме Original плитка, рамка и сердце повторяют пропорции кадра внутри квадратного слота. Выбор запоминается (`UserDefaults`).

#### 1.5. ✅ Результат работы не сохраняется
`selectedIDs` живёт только в памяти. Выход из приложения, падение, переход в Trash или Camera Roll ([PhotoStore.swift:111](Keepset/PhotoStore.swift:111)) — и все отметки пропали. Culling большой съёмки — это часы и несколько сессий.
- **Решение:**
  - Хранить выбор отдельно для каждой папки или среза: `[workspace: Set<ID>]` вместо одного общего набора. Переключение папок выбор не трогает.
  - Сохранять на диск (JSON в `Application Support`, ключ — путь папки / идентификатор среза). Для файлов можно ставить Finder-тег (`URLResourceValues.tagNames`): нативно и видно в Finder.
- **Сделано:** выбор хранится отдельно для каждой рабочей папки (ключ — режим + путь папки) в `Application Support/Keepset/selections.json` и сохраняется после каждого клика, drag, ⌘A, Cancel и операции. Переключение Sandbox / Camera Roll / Trash выбор не трогает. Исчезнувшие файлы при загрузке выпадают из выбора. Finder-теги не делал.

#### 1.6. Бинарная модель: «не решил» = «удалить»
Неотмеченное автоматически считается мусором. На большой съёмке так нельзя пройти в несколько проходов: например, сначала убрать явный брак, потом выбирать лучшие. Нельзя отличить «посмотрел и отверг» от «ещё не дошёл».
- **Решение (на выбор, см. вопросы):**
  - **A. Минимум:** считать «просмотренные». Коммит удаляет только неотмеченные из просмотренных, а остальные показывает отдельно: «48 not reviewed yet». Модель остаётся простой.
  - **B. Три состояния:** Keep ♥ / Reject ✕ / Undecided. Коммит удаляет только Reject; кнопка «Reject all undecided» — явное действие для тех, кому нужен нынешний режим.
  - Как минимум сразу: команда **Invert Selection** (`⌘⇧I`). Сейчас reject-сценарий спрятан за `⌘A` + снятие сердец.

#### 1.7. Нет группировки и сравнения похожих кадров
Серии (5–20 почти одинаковых кадров) — основная работа culling. Сейчас они просто стоят подряд.
- **Решение по шагам:**
  1. Группы по времени съёмки: разрыв больше N секунд — новая группа, заголовок секции в сетке. Дата берётся из EXIF через ImageIO или `creationDate` у PHAsset.
  2. Режим сравнения: выбрать 2–4 кадра → показать рядом с синхронным зумом.
  3. Позже: похожие кадры через Vision `VNGenerateImageFeaturePrintRequest` (нативно, без зависимостей), «лучший в серии» через `VNDetectFaceCaptureQualityRequest`.

#### 1.8. Camera Roll — одна лента на всю библиотеку
[CameraRollLibrary.swift:31-50](Keepset/CameraRollLibrary.swift:31). Сортировка — новые сверху, срезов нет. В Sandbox порядок по имени файла, в Camera Roll — по дате убывания, то есть порядок в режимах разный.
- **Решение:** в Camera Roll сначала выбрать срез — «Сегодня», «Последние 7 дней», день из списка, альбом. Работа и коммит идут внутри среза (см. 0.7). Внутри среза порядок хронологический по возрастанию: так снималось. Тот же порядок по дате съёмки — в Sandbox.

#### 1.9. Действие и фильтр называются одинаково
Сегмент фильтра «Delete N» и подпись «Delete N» на кнопке коммита — одно слово для фильтра и для действия. Кнопка называется «Keep N», а главный её эффект — удаление — написан мелко с прозрачностью 55% ([TopBar.swift:96-98](Keepset/TopBar.swift:96)). «Cancel» на деле означает «снять все отметки».
- **Решение:** фильтры — «All / Kept / Rest» (или «Not kept»). Кнопка — «Keep 12 · Trash 230», обе части читаемые. «Cancel» → «Deselect» (и убрать в меню, см. 0.2).

#### 1.10. Фильтры Keep/Delete прыгают под курсором
В фильтре Delete клик по кадру сразу убирает его из сетки с анимацией, и под курсор съезжает соседний. Следующий быстрый клик попадает не туда. Снятие последней отметки в Keep молча возвращает All ([PhotoStore.swift:288](Keepset/PhotoStore.swift:288)). Drag в фильтрах молча отключён, а лёгкое дрожание мыши при клике (≥4 px) там клик проглатывает ([PhotoStore.swift:149](Keepset/PhotoStore.swift:149) — якорь не ставится, и `endDragSelect` ничего не делает).
- **Решение:** в отфильтрованном виде менять состояние плитки на месте (затемнить или пометить), а состав сетки пересчитывать при повторном входе в фильтр. Пустой фильтр показывает пустое состояние, без автопрыжка. Клик с дрожанием в фильтрах работает как обычный toggle.

#### 1.11. Плохо видно, что отмечено
Белая рамка и белое сердце на светлом кадре (небо, снег) почти не видны. Неотмеченные никак не отличаются, хотя именно они уйдут в корзину.
- **Решение:** опция «Dim unmarked» (неотмеченные с opacity 0.5) — сразу видно, какой будет итог. У сердца — тёмная подложка-кружок.

#### 1.12. Нет прогресса
Непонятно, сколько осталось разобрать.
- **Решение:** в баре «Reviewed 120 / 240» (если сделать 1.6-A) или хотя бы позиция в loupe.

#### 1.13. Зум сетки
Слайдер работает инвертированно (`13 - x`, [TopBar.swift:60-64](Keepset/TopBar.swift:60)). Нет `⌘+` / `⌘-` и pinch.
- **Решение:** добавить `⌘=` / `⌘-` и `MagnifyGesture`. Запоминать число колонок (`@AppStorage`).

#### 1.14. Нет метаданных
Чтобы понять, почему кадр смазан, полезны выдержка, ISO, фокусное, время.
- **Решение:** строка EXIF в loupe (ImageIO `CGImageSourceCopyPropertiesAtIndex`), включается по `I`.

### P2 — Производительность

Для 21 демо-файла незаметно. Начнёт тормозить с ~1–2 тысяч, а Camera Roll на 30 тысяч уже сейчас.

#### 2.1. ✅ Декод тамбнейлов не отменяется
[ThumbnailLoader.swift:27](Keepset/ThumbnailLoader.swift:27): `Task.detached` не наследует отмену из `.task` ячейки. При быстром скролле в очереди копятся сотни декодов уже невидимых плиток. Для PhotoKit `withCheckedContinuation` тоже не отменяет `requestImage` ([ThumbnailLoader.swift:69](Keepset/ThumbnailLoader.swift:69)).
- **Решение:** `withTaskCancellationHandler`: отменять `PHImageManager.cancelImageRequest`, а для файлов проверять `Task.isCancelled` до начала декода. Ограничить параллелизм (простой семафор-актор на 4–6 декодов).
- **Сделано:** декод файлов идёт через `OperationQueue` на 4 потока. Отмена задачи ячейки снимает операцию из очереди до старта. Запрос PhotoKit отменяется через `cancelImageRequest`, continuation резюмится ровно один раз.

#### 2.2. ✅ Кэш без лимита по памяти
[ThumbnailLoader.swift:14](Keepset/ThumbnailLoader.swift:14): `countLimit = 400`. Плитка 900 px ≈ 2–3 МБ, превью 2200 px ≈ 13–19 МБ, и всё это в одном кэше. Худший случай — больше 1 ГБ.
- **Решение:** `totalCostLimit` (например, 300 МБ), `cost = bytesPerRow * height`. Превью держать в отдельном маленьком кэше.
- **Сделано:** `totalCostLimit` 300 МБ, стоимость записи = `bytesPerRow * height`. Отдельный кэш для превью не делал: крупные превью и так вытесняются первыми по стоимости.

#### 2.3. Полный декод вместо встроенного превью
`kCGImageSourceCreateThumbnailFromImageAlways: true` всегда декодирует полное изображение, даже когда в JPEG или RAW есть готовое встроенное превью.
- **Решение:** для сетки — `kCGImageSourceCreateThumbnailFromImageIfAbsent`, если встроенное превью не меньше нужного размера. Для loupe — полный декод. Для RAW это даёт выигрыш в разы.

#### 2.4. 🟡 Camera Roll: дорогой fetch и fetch на каждый тамбнейл
- [CameraRollLibrary.swift:39](Keepset/CameraRollLibrary.swift:39): `PHAssetResource.assetResources(for:)` на **каждый** ассет при загрузке. На 30 тысячах это десятки секунд. При этом весь `PHFetchResult` (ленивый) копируется в массив, и всё повторяется при каждом входе в Camera Roll ([PhotoStore.swift:114](Keepset/PhotoStore.swift:114)).
- [ThumbnailLoader.swift:59](Keepset/ThumbnailLoader.swift:59): `PHAsset.fetchAssets(withLocalIdentifiers:)` на каждую плитку.
- `deliveryMode = .highQualityFormat` + `isNetworkAccessAllowed = true` — для сетки это скачивание из iCloud ради плитки 420 px.
- **Решение:** имя файла запрашивать лениво (только в loupe). Держать `PHFetchResult` или `[id: PHAsset]` и брать ассет оттуда. `PHCachingImageManager` + `startCachingImages` для видимого диапазона. Для сетки — `.fastFormat` без сети, сеть только для loupe. Подписаться на `PHPhotoLibraryChangeObserver`, а не перезагружать всё. ⚠️ При `.opportunistic` колбэк вызывается дважды — continuation нельзя резюмить второй раз.
- **Сделано:** имя файла больше не читается для каждого ассета, превью запрашивает его лениво. Повторный вход в Camera Roll не перечитывает библиотеку. Обновление — по `PHPhotoLibraryChangeObserver`.
- **Осталось:** fetch ассета на каждую плитку, `PHCachingImageManager`, сеть только для loupe.

#### 2.5. 🟡 Хит-тест drag-а через фреймы всех ячеек
[PhotoGridView.swift:35-48](Keepset/PhotoGridView.swift:35): `GeometryReader` + `PreferenceKey` на каждой ячейке. Когда при скролле появляются и исчезают плитки, словарь меняется → `@State` → перерисовка всего грида. Поиск ячейки — `first(where:)` по словарю и по массиву, O(n) на каждое событие мыши. Невидимые ячейки фреймов не отдают, поэтому drag за край экрана невозможен, автоскролла нет.
- **Решение (проще и быстрее):** индекс считать арифметикой. Ширина ячейки известна из ширины контейнера и числа колонок: `index = row * columns + col`. Это O(1), работает для невидимых ячеек и убирает `PreferenceKey` целиком. Плюс автоскролл, когда курсор у края во время drag.
- **Сделано:** `GridGeometry.index(at:)` считает ячейку по ширине сетки и числу колонок. `PreferenceKey` на каждой ячейке убран, ширина берётся одним `onGeometryChange`. Слот ячейки квадратный в обоих режимах формы, поэтому арифметика верна и для Original.
- **Осталось:** автоскролл у края во время drag.

#### 2.6. Лишние пересчёты в сторе
- `displayedPhotos` — computed с фильтрацией, вызывается много раз за рендер ([ContentView.swift:16,28,30,33](Keepset/ContentView.swift:16)) и в `applyDragRange` на каждое событие ([PhotoStore.swift:180-184](Keepset/PhotoStore.swift:180)).
- `.animation(value: store.displayedPhotos.map(\.id))` ([ContentView.swift:61](Keepset/ContentView.swift:61)) — на каждый рендер строится и сравнивается массив всех id.
- **Решение:** анимировать по дешёвому ключу (`filter`, `mode`, счётчик ревизий списка). Индекс `[id: Int]` для `displayedPhotos` пересчитывать при изменении списка или фильтра, а не на каждое событие.

#### 2.7. ✅ Файловые операции на main thread
`PhotoStore` — `@MainActor`, а `FolderPhotoLibrary` синхронный. `loadPhotos`, `moveToTrash`, `resetFromSeed` блокируют UI. На внешнем диске или в папке на тысячи файлов это заметный фриз.
- **Решение:** вызывать библиотеку через `Task.detached` / `@concurrent` (она уже `Sendable`) и `await` результат.
- **Сделано:** load, Keep, Restore, Empty Trash и Reset идут через `Task.detached`. Состояние после `await` применяется к тому режиму, с которого операция началась. На main осталось только `WorkingPhotosDirectory.resolve()` при запуске: оно копирует seed один раз, в пустую папку.

#### 2.8. Внешние изменения папки не видны
Если файлы добавили в Finder, сетка не обновится до перезапуска. `didBecomeActive` перезагружает только Camera Roll и только без доступа ([ContentView.swift:91-94](Keepset/ContentView.swift:91)).
- **Решение (просто):** перечитывать папку при активации окна. Позже — `DispatchSource` / FSEvents.

- **Сделано:** таргет `KeepsetTests` (Swift Testing, в `project.yml`), 29 тестов: `GridGeometry`, сохранение выбора, диск вне main thread, загрузка Camera Roll, отмена и кэш миниатюр, форма плиток, `resolve` и отказ Reset без маркера (0.1).

#### 3.2. ✅ Стор нельзя протестировать: зависимости зашиты
`PhotoStore.init` сам вызывает `WorkingPhotosDirectory.resolve()`. `CameraRollLibrary` — статический enum с прямыми вызовами PhotoKit.
- **Решение:** минимальный протокол `PhotoSourceLibrary` (load / trash / restore) с двумя реализациями — Folder и CameraRoll — и фейк в тестах. Директорию передавать в `init`. Без DI-фреймворков.
- **Сделано:** протоколы `PhotoFolder`, `CameraRoll`, `SelectionStorage`. `PhotoStore.init` принимает их и `UserDefaults`, а `PhotoStore()` собирает рабочие реализации.

#### 3.3. Повторы условий режима
`mode == .sandbox || mode == .cameraRoll` повторяется 7 раз (PhotoStore, TopBar, ContentView).
- **Решение:** `WorkspaceMode.isCullable` (или `.allowsKeep`).

#### 3.4. Кнопки без нормального поведения
`FillHitButtonStyle` ([TopBar.swift:208-213](Keepset/TopBar.swift:208)) заменяет кнопку на `onTapGesture`. Нет состояния нажатия, нет активации с клавиатуры, хуже доступность.
- **Решение:** `ButtonStyle` с `configuration.isPressed` и `contentShape` — хит-зона останется той же.

#### 3.5. Горячие клавиши спрятаны
`⌘A`, `Esc`, `Return` повешены на скрытые кнопки ([ContentView.swift:74-84](Keepset/ContentView.swift:74)), в меню их нет. Пользователь о них не узнает.
- **Решение:** `CommandMenu("Selection")` / `CommandGroup` в меню Edit: Select All, Deselect, Invert, Undo, Keep…, Open in Viewer. Так клавиши становятся видимыми, и это стандарт macOS.

#### 3.6. Доступность
У плиток нет `accessibilityLabel` (имя файла), нет `.isSelected`, нет действий. VoiceOver фактически не работает.
- **Решение:** `.accessibilityElement`, label = filename, `.accessibilityAddTraits(isSelected ? .isSelected : [])`, `.accessibilityAction` для toggle и preview.

#### 3.7. Мелкие баги
- `LoupeButton.onDisappear { onPreview(false) }` ([PhotoCell.swift:120](Keepset/PhotoCell.swift:120)) закрывает превью, даже если исчезла **другая** ячейка, например при перелейауте. Нужно передавать, чьё это превью, и закрывать только своё.
- Ключ кэша `photo.id::maxPixel` не учитывает `modifiedAt`: файл, заменённый под тем же именем (Reset), покажет старый тамбнейл.
- `WindowHookView` красит superview кнопки закрытия ([ContentView.swift:224](Keepset/ContentView.swift:224)) — хрупкая опора на внутреннюю иерархию AppKit. С `.windowStyle(.hiddenTitleBar)` и `.toolbarBackground` (macOS 15) или просто `window.backgroundColor` этого, скорее всего, хватит. Проверить и удалить.

#### 3.8. Два источника правды для проекта
В репозитории лежат и `project.yml` (XcodeGen), и `Keepset.xcodeproj`. Со временем они разойдутся.
- **Решение:** выбрать одно. Либо генерировать `.xcodeproj` и не коммитить его, либо удалить `project.yml`.

#### 3.9. Демо-фото в бандле и в git
Папка `photos/` (7,9 МБ AVIF) копируется в ресурсы приложения ([project.yml](project.yml)) и меняется в git: сейчас в рабочем дереве удалённые и новые файлы плюс неотслеживаемая `photo-set/`. Для продукта seed в бандле не нужен, а бинарники раздувают историю.
- **Решение:** seed оставить только в Debug-конфигурации или скачивать по кнопке. Не коммитить смену демо-набора. `photo-set/` либо в `.gitignore`, либо удалить.

### P4 — Возможности и полировка

#### 4.1. Нативная корзина вместо своей `.Trash`
Своя скрытая `.Trash` внутри папки путается с системными `.Trashes`, не видна в Finder и требует своего Empty Trash.
- **Решение (рекомендация):** `FileManager.trashItem(at:resultingItemURL:)` — системная Корзина с «Put Back» в Finder. В приложении можно хранить список отправленных за последнюю сессию, чтобы работали Restore и Undo. Минус: Корзина общая, нельзя очистить только «своё». Решить (см. вопросы).

#### 4.2. Открыть любую папку
Сейчас только захардкоженная `photos/`. Для реального использования нужно `File → Open Folder…` (`NSOpenPanel`), список недавних и drag-n-drop папки на окно.

#### 4.3. RAW и пары RAW+JPEG
Расширения ([PhotoLibrary.swift:18](Keepset/PhotoLibrary.swift:18)) не включают RAW (`dng`, `cr2`, `cr3`, `nef`, `arw`, `raf`, `orf`, `rw2`), а фотографы отбирают именно их. ImageIO читает RAW нативно.
- **Решение:** добавить RAW-расширения. Файлы с одинаковым именем и разными расширениями (`IMG_1.CR3` + `IMG_1.JPG`) считать одним кадром: отметка и удаление — для обоих. То же для `.xmp`-сайдкаров.

#### 4.4. Ограниченный доступ к Фототеке
`.limited` считается полным доступом ([CameraRollLibrary.swift:24](Keepset/CameraRollLibrary.swift:24)), и изменить набор фото нельзя.
- **Решение:** при `.limited` показать кнопку «Select More Photos…» (`PHPhotoLibrary.shared().presentLimitedLibraryPicker`).

#### 4.5. Обратная связь
- Индикатор занятости виден только при пустой сетке. Во время Keep на большом наборе нужен прогресс в баре.
- Ошибка — всегда «Something went wrong». Лучше конкретно: «Couldn't move 3 photos: permission denied».
- Тост после коммита: «Kept 12 · 230 moved to Trash · Undo».

#### 4.6. Именование и документация
- В UI «Trash», в меню «Recently Deleted», в README «Recently Deleted», на диске `.Trash`. Нужен один термин.
- `project.md` — по-русски, `README.md` — по-английски, и они местами расходятся. После изменений из этого плана обновить оба.
- Меню называется «Sandbox», а в нём «Recently Deleted» и «Show Photos Folder» — это не про песочницу. После 4.2 разнести по File / View / Go.
