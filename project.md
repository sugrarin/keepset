# Keepset

macOS-приложение для разбора папки с фото: отмечаешь то, что хочешь оставить, остальное уходит во внутреннюю корзину и оттуда его можно вернуть.

Рабочее имя продукта в бандле — **Keepset** (`com.keepset.app`). Репозиторий называется `keepset`. Сейчас это песочница плюс Camera Roll: приложение крутится вокруг локальной папки `photos/` и системной Фототеки.

Версия: `1.0`. Платформа: macOS 14+, Swift 6, SwiftUI + AppKit.

---

## Зачем это нужно

Задача не «удалить выбранное», а наоборот: **выбрать то, что оставляем**. Всё неотмеченное считается мусором и по Keep переезжает в корзину приложения.

Это ближе к разбору съёмки, чем к обычному Finder: смотришь сетку, отмечаешь удачные кадры, остальное ещё лежит в Recently Deleted.

---

## Что видит пользователь

Одно тёмное окно. Сверху свой бар (не системный toolbar), под ним квадратная сетка.

### Режимы

Приложение всегда находится в одной из трёх рабочих папок. Переключение — первый контрол слева в баре, плашка с названием папки и иконкой `chevron.up.chevron.down`.

**Sandbox (по умолчанию).** Клик по фото сразу выбирает его. Порядок в баре: папка, слайдер, форма плиток, затем сегменты **All N / Keep N / Delete N**: они только фильтруют сетку, флаги выбора не трогают. По умолчанию открыт All. Пустой сегмент неактивен. Как только есть выбор, справа появляются **Cancel** и двухэтажная кнопка **Keep N / Delete N**. Она сразу выполняет операцию: выбранное остаётся в папке, остальное переезжает в Trash. Подтверждений нет: на месте кнопок появляется **Deleted N [Undo]**. Undo возвращает перенесённые файлы и прежние сердца. Плашка пропадает, как только начат новый выбор, а также после Restore, Empty Trash и Reset.

**Camera Roll.** Системная Фототека через PhotoKit. Тот же Keep/Delete: неотмеченное уходит в «Недавно удалённые» Фото, не во внутреннюю корзину приложения. Если доступа нет, показывается кнопка в системные настройки.

**Trash.** Внутренняя корзина. Можно выбрать фото и нажать **Restore**, либо **Empty Trash**, если ничего не выбрано. Выход — через меню папки в заголовке.

### Сетка и жесты

- Клик переключает одно фото.
- Зажал и потащил — интервал от стартового фото до текущего в порядке сетки. Операция фиксируется на старте: начали с пустого — отмечаем диапазон, начали с сердца — снимаем. Кто выпал из интервала, пока кнопку не отпустили, возвращается как было.
- Наведение на ячейку показывает иконку лупы внизу. Превью открывается только с иконки и только после **120 мс** наведения, чтобы проезд мыши не вспыхивал оверлеем.
- Все плитки со скруглением 8 pt. Выбранные кадры уменьшаются на 3%, плюс белая рамка 4 pt. Вместо чекбокса — сердце: контур `heart` при наведении, `heart.fill` после клика. Фон `#18191C`, акцент белый, подложки и вторичные кнопки `#2B2C2F`.
- Слайдер в баре: подложка с линией и светлой ручкой. Слева минимум (мелкая сетка), справа максимум (крупные плитки). Колонок от 3 до 10.
- Сразу после слайдера переключатель формы плиток: квадрат (`square`) или оригинальные пропорции кадра (`rectangle.portrait`). Выбор запоминается.
- Отметки сохраняются между запусками и при переключении папок, отдельно для каждой рабочей папки.

### Клавиши и меню Sandbox

| Действие | Как |
|---|---|
| Выбрать все | `⌘A` |
| Keep (с удалением неотмеченных) / Restore | `Return` |
| Вернуть последнее удаление | `⌘Z` |
| Снять выбор | `Esc` |
| Сбросить демо-папку | `⌘⇧R` |
| Открыть корзину | `⌘⇧T` |
| Показать папку с фото | меню Sandbox → Show Photos Folder |

## Логика данных

Источник правды — файловая система, не база.

```
photos/                 ← живая библиотека (то, что ещё «в игре»)
photos/.Trash/          ← recently deleted, не системная Корзина macOS
```

`Photo.id` — это путь файла. После move в `.Trash` или обратно id меняется, потому что меняется путь. Это нормально: списки после операции перечитываются с диска.

Поддерживаемые расширения: `jpg`, `jpeg`, `png`, `heic`, `heif`, `webp`, `avif`, `gif`, `tif`, `tiff`, `bmp`.

### Куда указывает рабочая папка

`WorkingPhotosDirectory.resolve()` выбирает папку так:

1. Переменная окружения `KEEPSET_PHOTOS_DIR`. В Xcode-схеме она равна `$(SRCROOT)/photos`, поэтому из Xcode приложение всегда работает с репозиторной папкой. Если такой папки нет, приложение создаёт её и помечает маркером.
2. Иначе `~/Library/Application Support/Keepset/photos`. Если она пустая, туда копируется seed из ресурсов бандла.

Соседние папки `photos/` приложение больше не ищет. Раньше оно поднималось вверх от cwd и бандла, а на регистронезависимой APFS под это имя подходит и `~/Photos`.

Seed — те же демо-файлы из `photos/`, они ещё и кладутся в бандл как resources. Reset Demo Photos стирает текущую папку и `.Trash`, затем копирует seed заново.

Reset удаляет файлы навсегда, поэтому работает только в папке с маркером `.keepset-sandbox`. Его ставит само приложение (Application Support или созданная им папка из env), у репозиторной `photos/` он лежит в git. В папке без маркера Reset показывает ошибку и ничего не трогает.

Файлы внутри `.app` приложение не двигает и не удаляет (`canMutate`).

### Keep → Trash

По нажатию Keep в корзину уходит всё, чего **нет** в `selectedIDs`. Если снять все сердца, кнопка пропадает: удалить всю библиотеку одним жестом нельзя. Фильтры Keep/Delete позволяют перед этим посмотреть, что останется и что уйдёт.

Restore делает обратный `moveItem` в `photos/`. Empty Trash уже удаляет файлы навсегда (`removeItem`), не через системную Корзину.

При конфликте имён (`cat.jpg` уже есть) к имени добавляется `-2`, `-3`, …

## Как это устроено в коде

Слой тонкий: нет SwiftData, нет сети. Песочница читает папку с диска, Camera Roll — PhotoKit. Состояние живёт в одном `@Observable` сторе, UI — набор SwiftUI-вью.

```
KeepsetApp
  └─ PhotoStore (environment)
       └─ ContentView
            ├─ TopBar
            ├─ PhotoGridView → PhotoCell
            └─ PreviewOverlay
```

| Файл | Роль |
|---|---|
| `KeepsetApp.swift` | Точка входа, окно, меню Sandbox, `PhotoStore` как `@State` |
| `PhotoStore.swift` | Режимы, фильтр All/Keep/Delete, выбор, жесты диапазона, keep/restore |
| `PhotoLibrary.swift` | Резолв папки, чтение, move в `.Trash` / обратно, reset seed |
| `CameraRollLibrary.swift` | Доступ к Фототеке, fetch PHAsset, удаление в Recently Deleted |
| `Photo.swift` | Модель: id, source (file/asset), filename, modifiedAt |
| `ContentView.swift` | Сборка экрана, превью, клавиши, пустые состояния, настройка NSWindow |
| `TopBar.swift` | Слайдер, фильтр, меню папки, Cancel/Keep/Restore |
| `PhotoGridView.swift` | `LazyVGrid`, hit-test ячеек по фреймам |
| `PhotoCell.swift` | Квадратный превью, сердце, лупа, клик и drag |
| `PreviewOverlay.swift` | Полноэкранный просмотр по наведению на лупу |
| `ThumbnailLoader.swift` | Тамбнейлы: ImageIO для файлов, PHImageManager для Camera Roll |
| `GridGeometry.swift` | Арифметика сетки: какая ячейка под точкой |
| `SelectionFile.swift` | Сохранение отметок по папкам в JSON |

### Состояние: `PhotoStore`

`WorkspaceMode`: `sandbox` | `cameraRoll` | `trash`. `PhotoFilter`: `all` | `keep` | `delete`.

Важные поля:

- `photos` / `cameraRollPhotos` / `trashedPhotos` — три списка: папка, Фототека, внутренняя корзина.
- `selectedIDs` — набор сердец текущей папки (вычисляется из `selections`). Смысл зависит от папки: в sandbox/camera roll это «оставить», в trash — «восстановить».
- `selections` — сердца по всем папкам, ключ — режим + путь папки. Хранится в `Application Support/Keepset/selections.json` (`SelectionFile`) и сохраняется после каждого изменения.
- `tileShape` — `square` | `original`, хранится в `UserDefaults`.
- `filter` — какой срез сетки показать. Переключение фильтра не меняет `selectedIDs`. Если текущий фильтр опустел, стор возвращает All.
- `displayedPhotos` — что реально рисует сетка.

Переходы:

```
sandbox --Keep N / Delete N--> sandbox (неотмеченные в Trash)
  ^
  +--folder menu / ⌘⇧T--> trash --Restore / folder menu--> sandbox
```

Drag-select — интервал в порядке сетки. На `pointer down` стор запоминает якорь, снимок `selectedIDs` и операцию (якорь был пустой → отметить, с сердцем → снять). Пока курсор на той же ячейке, это клик. Как только попали в другую, к интервалу `[якорь … текущее]` применяется только эта операция поверх снимка: уже отмеченное при «отметить» не меняется, уже пустое при «снять» тоже. Обратное движение интервал сужает, выпавшие кадры возвращаются к снимку. В фильтрах Keep/Delete drag отключён: смена флагов меняла бы состав сетки прямо во время жеста.

### Сетка

`PhotoGridView` вешает именованное координатное пространство `photoGrid` и одним `onGeometryChange` узнаёт его ширину. `DragGesture` на ячейке отдаёт точку в этом пространстве, а `GridGeometry.index(at:)` арифметикой находит ячейку под курсором — в том числе невидимую. Отсюда интервал считается по порядку в сетке, в том числе при переходе на следующую строку.

Слот ячейки всегда квадратный (`aspectRatio(1)`), на этом держится арифметика хит-теста. В режиме Square картинка `scaledToFill` на весь слот, в режиме Original плитка вписывается в слот с пропорциями кадра. Размер тамбнейла зависит от числа колонок: 900 / 640 / 420 px по длинной стороне.

Лупа — отдельный hit-target. У неё свой `highPriorityGesture`, чтобы клик по иконке не переключал выбор. Превью — оверлей на всё окно, без hit-testing: курсор остаётся на лупе.

### Окно

`.windowStyle(.hiddenTitleBar)` плюс `fullSizeContentView` и прозрачный системный title bar, который красится в чёрный. Контент **не** заезжает под traffic lights: `TopBar` стоит обычным рядом в `VStack` ниже safe area, сетка под баром клипается. Поэтому при скролле фото не просвечивают сквозь хром.

### Тамбнейлы

`ThumbnailLoader` — синглтон. Ключ кэша: `path + maxPixel`, лимит кэша — 300 МБ по байтам картинок. Декод идёт в `OperationQueue` на 4 потока через `CGImageSourceCreateThumbnailAtIndex`, с учётом ориентации. Если ячейка ушла с экрана до старта декода, операция отменяется. Запросы PhotoKit тоже отменяются. Превью лупы просит 2200 px, сетка — меньше.

### Диск и Фототека

Стор получает зависимости через протоколы: `PhotoFolder` (папка и `.Trash`), `CameraRoll` (PhotoKit), `SelectionStorage` (файл выбора). Все операции с диском идут через `Task.detached`, не на main thread. Camera Roll читается один раз при первом входе, дальше — по `PHPhotoLibraryChangeObserver`. Имя файла ассета читается лениво, только для превью.

## Сборка и запуск

Проект генерируется/описан в `project.yml` (XcodeGen), в репозитории уже лежит `Keepset.xcodeproj`.

```
xcodebuild -project Keepset.xcodeproj -scheme Keepset -configuration Debug -derivedDataPath build build
```

Единственный Debug-бандл — `build/Build/Products/Debug/Keepset.app`. DerivedData в `~/Library/Developer/Xcode` для этого проекта не используется, чтобы Spotlight/Alfred не открывали старую копию.

Схема подставляет `KEEPSET_PHOTOS_DIR=$(SRCROOT)/photos`. Если открыть `.app` без этой переменной (например, `open build/Build/Products/Debug/Keepset.app`), приложение работает с `~/Library/Application Support/Keepset/photos`, а не с репозиторной `photos/`.

Подпись локальная (`CODE_SIGN_IDENTITY: "-"`), hardened runtime включён, в entitlements — доступ к Фототеке.

## Чего здесь пока нет

Это сознательно узкий клиент, не полноценная замена Фото.

- Camera Roll читает Фототеку и удаляет в системные «Недавно удалённые»; внутренняя корзина приложения — только для Sandbox.
- Нет синхронизации, аккаунтов, облака.
- Корзина приложения не самоочищается по времени.
- Undo есть только для последнего Keep в Sandbox. В Camera Roll его нет: PhotoKit не умеет возвращать из «Недавно удалённых».
- Тесты покрывают только часть логики (`KeepsetTests`, Swift Testing): запуск через `xcodebuild … test`.

Демо-файлы лежат в `photos/`. `.Trash` в git не коммитится.
