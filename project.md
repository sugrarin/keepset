# Trasher

macOS-приложение для разбора папки с фото: отмечаешь то, что хочешь оставить, остальное уходит во внутреннюю корзину и оттуда его можно вернуть.

Рабочее имя продукта в бандле — **Trasher** (`com.trasher.app`). Репозиторий называется `photo-keeper`. Сейчас это песочница: приложение крутится вокруг локальной папки `photos/`, а не вокруг системной Фототеки.

Версия: `0.1.0`. Платформа: macOS 14+, Swift 6, SwiftUI + AppKit.

---

## Зачем это нужно

Задача не «удалить выбранное», а наоборот: **выбрать то, что оставляем**. Всё неотмеченное считается мусором и по Keep переезжает в корзину приложения.

Это ближе к разбору съёмки, чем к обычному Finder: смотришь сетку, отмечаешь удачные кадры, остальное ещё лежит в Recently Deleted.

---

## Что видит пользователь

Одно тёмное окно. Сверху свой бар (не системный toolbar), под ним квадратная сетка.

### Режимы

Приложение всегда находится в одной из трёх рабочих папок. Переключение — заголовок по центру бара с иконкой `chevron.up.chevron.down`.

**Sandbox (по умолчанию).** Клик по фото сразу выбирает его. Слева от заголовка, сразу после слайдера, сегменты **All N / Keep N / Delete N**: они только фильтруют сетку, флаги выбора не трогают. По умолчанию открыт All. Пустой сегмент неактивен. Как только есть выбор, справа появляются **Cancel** и двухэтажная кнопка **Keep N / Delete N**. Она сразу выполняет операцию: выбранное остаётся в папке, остальное переезжает в Trash.

**Camera Roll.** Системная Фотоплёнка. Пока не подключена: сетка пустая.

**Trash.** Внутренняя корзина. Можно выбрать фото и нажать **Restore**, либо **Empty Trash**, если ничего не выбрано. Выход — через меню папки в заголовке.

### Сетка и жесты

- Клик переключает одно фото.
- Зажал и потащил — выделяется непрерывный диапазон **по порядку в сетке**, в том числе при переходе на следующую строку. Это не прямоугольная рамка, а диапазон индексов, как в Фото на iOS.
- Наведение на ячейку показывает иконку лупы внизу. Превью открывается только с иконки и только после **120 мс** наведения, чтобы проезд мыши не вспыхивал оверлеем.
- Все плитки со скруглением 8 pt. Выбранные кадры уменьшаются на 3%, плюс рамка 4 pt акцентного цвета `#5095F7`. Вместо чекбокса — сердце: контур `heart` при наведении, `heart.fill` после клика. Фон `#18191C`, подложки и вторичные кнопки `#2B2C2F`.
- Слайдер в баре меняет число колонок от 3 до 10.

### Клавиши и меню Sandbox

| Действие | Как |
|---|---|
| Выбрать все | `⌘A` |
| Keep (с удалением неотмеченных) / Restore | `Return` |
| Снять выбор | `Esc` |
| Сбросить демо-папку | `⌘⇧R` |
| Открыть корзину | `⌘⇧T` |
| Показать папку с фото | меню Sandbox → Show Photos Folder |

## Логика данных

Источник правды — файловая система, не база.

```
photos/                 ← живая библиотека (то, что ещё «в игре»)
photos/.Trash/          ← recently deleted, не системная Корзина macOS
```

`Photo.id` — это путь файла. После move в `.Trash` или обратно id меняется, потому что меняется путь. Это нормально: списки после операции перечитываются с диска.

Поддерживаемые расширения: `jpg`, `jpeg`, `png`, `heic`, `heif`, `webp`, `avif`, `gif`, `tif`, `tiff`, `bmp`.

### Куда указывает рабочая папка

`WorkingPhotosDirectory.resolve()` ищет папку в таком порядке:

1. Переменная окружения `TRASHER_PHOTOS_DIR`. В Xcode-схеме она равна `$(SRCROOT)/photos`, поэтому из Xcode приложение всегда работает с репозиторной папкой.
2. Папка `photos/` где-то рядом с cwd или бандлом, но **не внутри** `.app`.
3. Иначе `~/Library/Application Support/Trasher/photos`. Если она пустая, туда копируется seed из ресурсов бандла.

Seed — те же демо-файлы из `photos/`, они ещё и кладутся в бандл как resources. Reset Demo Photos стирает текущую папку и `.Trash`, затем копирует seed заново.

Файлы внутри `.app` приложение не двигает и не удаляет (`canMutate`).

### Keep → Trash

По нажатию Keep в корзину уходит всё, чего **нет** в `selectedIDs`. Если снять все сердца, кнопка пропадает: удалить всю библиотеку одним жестом нельзя. Фильтры Keep/Delete позволяют перед этим посмотреть, что останется и что уйдёт.

Restore делает обратный `moveItem` в `photos/`. Empty Trash уже удаляет файлы навсегда (`removeItem`), не через системную Корзину.

При конфликте имён (`cat.jpg` уже есть) к имени добавляется `-2`, `-3`, …

## Как это устроено в коде

Слой тонкий: нет SwiftData, нет сети, нет PhotoKit. Состояние живёт в одном `@Observable` сторе, диск — в `FolderPhotoLibrary`, UI — набор SwiftUI-вью.

```
TrasherApp
  └─ PhotoStore (environment)
       └─ ContentView
            ├─ TopBar
            ├─ PhotoGridView → PhotoCell
            └─ PreviewOverlay
```

| Файл | Роль |
|---|---|
| `TrasherApp.swift` | Точка входа, окно, меню Sandbox, `PhotoStore` как `@State` |
| `PhotoStore.swift` | Режимы, фильтр All/Keep/Delete, выбор, жесты диапазона, keep/restore |
| `PhotoLibrary.swift` | Резолв папки, чтение, move в `.Trash` / обратно, reset seed |
| `Photo.swift` | Модель: id, url, filename, modifiedAt |
| `ContentView.swift` | Сборка экрана, превью, клавиши, пустые состояния, настройка NSWindow |
| `TopBar.swift` | Слайдер, фильтр, меню папки, Cancel/Keep/Restore |
| `PhotoGridView.swift` | `LazyVGrid`, hit-test ячеек по фреймам |
| `PhotoCell.swift` | Квадратный превью, сердце, лупа, клик и drag |
| `PreviewOverlay.swift` | Полноэкранный просмотр по наведению на лупу |
| `ThumbnailLoader.swift` | ImageIO-тамбнейлы с `NSCache` |

### Состояние: `PhotoStore`

`WorkspaceMode`: `sandbox` | `cameraRoll` | `trash`. `PhotoFilter`: `all` | `keep` | `delete`.

Важные поля:

- `photos` / `trashedPhotos` — два списка с диска.
- `selectedIDs` — текущий набор сердец. Смысл зависит от папки: в sandbox это «оставить», в trash — «восстановить».
- `filter` — какой срез сетки показать. Переключение фильтра не меняет `selectedIDs`. Если текущий фильтр опустел, стор возвращает All.
- `displayedPhotos` — что реально рисует сетка.

Переходы:

```
sandbox --Keep N / Delete N--> sandbox (неотмеченные в Trash)
  ^
  +--folder menu / ⌘⇧T--> trash --Restore / folder menu--> sandbox
```

Drag-select хранит якорь, снимок выбора на старте жеста и флаг «уже сдвинулись на другое фото». Пока курсор на той же ячейке, это клик (toggle). Как только попали в другую, в выбор добавляется диапазон `[anchor … current]` поверх снимка. Обратное движение диапазон сужает. В фильтрах Keep/Delete drag отключён: смена флагов меняла бы состав сетки прямо во время жеста.

### Сетка

`PhotoGridView` вешает именованное координатное пространство `photoGrid` и собирает фреймы ячеек через `PreferenceKey`. `DragGesture` на ячейке отдаёт точку в этом пространстве, грид находит, какая ячейка под курсором. Отсюда и «перескочил на следующую строку — выделилось всё по порядку», а не «всё, над чем проехал курсор».

Ячейка квадратная (`aspectRatio(1)`), картинка `scaledToFill`. Размер тамбнейла зависит от числа колонок: 900 / 640 / 420 px по длинной стороне.

Лупа — отдельный hit-target. У неё свой `highPriorityGesture`, чтобы клик по иконке не переключал выбор. Превью — оверлей на всё окно, без hit-testing: курсор остаётся на лупе.

### Окно

`.windowStyle(.hiddenTitleBar)` плюс `fullSizeContentView` и прозрачный системный title bar, который красится в чёрный. Контент **не** заезжает под traffic lights: `TopBar` стоит обычным рядом в `VStack` ниже safe area, сетка под баром клипается. Поэтому при скролле фото не просвечивают сквозь хром.

### Тамбнейлы

`ThumbnailLoader` — синглтон. Ключ кэша: `path + maxPixel`. Декод идёт в `Task.detached` через `CGImageSourceCreateThumbnailAtIndex`, с учётом ориентации. Превью лупы просит 2200 px, сетка — меньше.

## Сборка и запуск

Проект генерируется/описан в `project.yml` (XcodeGen), в репозитории уже лежит `Trasher.xcodeproj`.

```
xcodebuild -project Trasher.xcodeproj -scheme Trasher -configuration Debug -derivedDataPath build build
```

Единственный Debug-бандл — `build/Build/Products/Debug/Trasher.app`. DerivedData в `~/Library/Developer/Xcode` для этого проекта не используется, чтобы Spotlight/Alfred не открывали старую копию.

Схема подставляет `TRASHER_PHOTOS_DIR=$(SRCROOT)/photos`. Если открыть `.app` без этой переменной, приложение либо найдёт соседний `photos/`, либо уйдёт в Application Support.

Подпись локальная (`CODE_SIGN_IDENTITY: "-"`), hardened runtime включён, entitlements пустые.

## Чего здесь пока нет

Это сознательно узкая песочница, не клиент Фототеки.

- Нет PhotoKit / доступа к системной медиатеке, хотя в Info.plist уже есть usage-строка на будущее.
- Нет синхронизации, аккаунтов, облака.
- Корзина не самоочищается по времени (в отличие от «Недавно удалённые» в Фото).
- Нет undo кроме самой корзины.
- Нет тестов.

Демо-файлы лежат в `photos/`. `.Trash` в git не коммитится.
